# Шифрованные резервные копии Production в PS Cloud

Облачная служба дополняет локальные копии, создаваемые ежедневно в 00:00
`Asia/Almaty`. Только Production отправляет данные в облако. Test продолжает
создавать локальные копии без облачной конфигурации.

## Назначение и защита

- PS Cloud, проект `15303`, бакет `oxus-prod-backups-locked`.
- В консоли подтверждены Алматы (`kz-ala-1`) и универсальное хранилище.
- Endpoint `https://object.pscloud.io`, path-style S3; API возвращает location `kz`.
- Бакет приватный, versioning и Object Lock включены при его создании.
- Архивы шифруются `age` до отправки. На Production находится только открытый
  X25519 recipient. Закрытая identity хранится на Mac и отдельно в защищённом
  хранилище владельца. Она не включается в Git, серверную конфигурацию или облако.
- Каждый архив и его запись завершения получают COMPLIANCE на 7 суток.
  Даже владелец не может удалить эту версию до окончания блокировки.
- `complete.json` содержит только идентификатор точки, время, размер,
  SHA-256, открытый recipient и version ID. Манифест с конфигурацией приложения
  находится внутри шифрованного архива.

Пользователь загрузки: `15303_oxus-backup-uploader`. Его внутренний S3 ID,
подтверждённый запросом `GET /`, — `a74e83900e1eae5c7dd2d3fe889127f4`.
Именно этот ID используется в `aws:username`; отображаемое имя панели PS
в этом условии не сработало.

В новом бакете примените целиком [pscloud-policy.json](pscloud-policy.json).
Она разрешает чтение настроек бакета и операции с объектами только внутри
`oxus-backup/v1/production/`. Она не разрешает менять bucket policy, ACL,
versioning или конфигурацию Object Lock, удалять бакет или обходить блокировку.

После применения политики можно удалить отдельное ACL-назначение «Чтение,
Запись» пользователя загрузки: все необходимые операции перечислены в политике.
Права основного владельца `15303` сохраняются. Бакет остаётся приватным.
Повторите проверку `--check-locked-bucket`: подписанные запросы должны быть 200,
анонимные — 403. Ключ основного владельца для работы службы не нужен.

## Расписание, повтор и ротация

Локальный timer и `oxus_backup.py` не изменяются. Новая облачная служба не
вызывает остановку, запуск или восстановление контейнеров приложения.
Её timer проверяет завершённые точки каждый час в `:10` по Алматы.
Обычно новая копия появляется после полуночного локального запуска;
остальные проверки повторяют неудачную передачу или проверяют ротацию.

Передача использует все ещё сохранённые локальные ежедневные точки и последнюю
успешную воскресную. Уже опубликованная точка повторно не шифруется и не
загружается. Снимок считается облачной точкой только после скачивания конкретной
версии шифротекста, проверки его SHA-256 и чтения записи завершения.

Файлы локальной точки открываются под общим deployment lock. Блокировка
освобождается перед шифрованием и сетью. Открытые файловые дескрипторы позволяют
закончить передачу, даже если локальная ротация уже удалила имена этих файлов.
Новая локальная plaintext-копия не создаётся.

Сбой передачи оставляет одну отслеживаемую точку в шифрованном spool. Она
завершается перед следующей точкой: повторяющаяся ошибка не создаёт новый
незавершённый архив каждый день. Multipart передача использует части по 16 MiB;
после обрыва известный multipart отменяется перед повтором. Незавершённые
управляемые multipart старше часа также отменяются.

После multipart-загрузки служба читает защиту конкретной версии. Если S3
вернул `ObjectLockConfigurationNotFoundError` или пустую настройку retention,
служба отдельно устанавливает COMPLIANCE на этой версии и проверяет ответ
повторным чтением. До подтверждения защиты и SHA-256 запись `complete.json`
не создаётся. Между завершением загрузки и установкой защиты версия может
оставаться незаблокированной. При отказе повтор использует тот же шифротекст
и version ID; более долгий существующий срок защиты не сокращается.

Ротация хранит последние 7 успешных ежедневных дат и последнюю успешную
воскресную точку. Пересекающаяся ежедневная/еженедельная точка не дублируется.
COMPLIANCE может временно оставить дополнительные устаревшие точки,
в особенности при первой выгрузке старых локальных копий. Они удаляются после
окончания 7 суток защиты, с двухминутным запасом по времени. Обработка идёт по
конкретным version ID, включая неактуальные версии. Delete marker вместо
удаления версии не используется. Неизвестные ключи внутри управляемого prefix
останавливают удаление и требуют проверки. Данные вне этого prefix не удаляются.

Если последняя локальная точка старше 30 часов, облачный запуск завершается
ошибкой и не выполняет ротацию. Journal и `last-run.json` показывают сбои;
внешние уведомления отдельно не настроены.

## Установка на Production

Не запускайте этот installer на Test. Он проверяет Production store и
`STAGING=false` до создания конфигурации. Установленный локальный скрипт должен
побайтно совпадать с приложенной проверенной версией.

На Production:

```bash
apt-get update
NEEDRESTART_MODE=l apt-get install -y age python3-boto3
```

На Mac передайте только открытый recipient:

```bash
scp -o StrictHostKeyChecking=yes \
  /Users/johnycarlson/oxus-backup-keys/production.recipient.txt \
  root@87.106.144.28:/root/production.recipient.txt
```

После доставки проверенного каталога `deployment/backup` в приватный staging
каталог сервера запустите:

```bash
bash /root/REVIEWED-STAGING/deployment/backup/install-cloud.sh /root/production.recipient.txt
```

Installer использует существующие ключи загрузчика из
`/etc/oxus-backup/pscloud.json` (root 600). Старое поле bucket в этом файле
может оставаться `oxus-prod-backups`; новый целевой бакет задаётся отдельно в
`/etc/oxus-backup/cloud.json`. Ключи не копируются в `.env` и не меняются.

Installer добавляет программу, state и systemd units, выполняет GET-проверку,
но не запускает выгрузку и не включает новый timer.

## Первая проверка, выгрузка и включение расписания

На Production, по очереди:

```bash
python3 /usr/local/lib/oxus-backup/oxus_cloud_backup.py probe
python3 /usr/local/lib/oxus-backup/oxus_cloud_backup.py run
python3 /usr/local/lib/oxus-backup/oxus_cloud_backup.py verify
python3 /usr/local/lib/oxus-backup/oxus_cloud_backup.py status
```

`probe` загружает только небольшой шифрованный тестовый объект, проверяет
скачивание, COMPLIANCE и отказ в удалении именно его версии. Этот объект
сохраняется до окончания блокировки; повтор не создаёт новый объект.
Обычная выгрузка требует успешной probe-записи для текущего recipient.

Ожидаемые статусы: `CLOUD_WRITE_READ_LOCK_PROBE_PASS`,
`CLOUD_BACKUP_COMPLETE`, `CLOUD_CIPHERTEXT_INTEGRITY_VERIFIED`.
`status` показывает свежесть исходных данных, последнюю точку, состояние
последнего запуска и наличие незавершённой передачи.
Старый `oxus_backup.py status` по-прежнему описывает только локальные копии
и сохраняет `local_only: true`; для состояния облака используйте новый status.

После проверки скачанного архива на Mac включите timer:

```bash
systemctl enable --now oxus-cloud-backup.timer
systemctl list-timers oxus-cloud-backup.timer --all --no-pager -l
```

Первый автоматический запуск произойдёт в ближайший час `:10`. Это только
передача завершённых локальных точек; дополнительного обслуживания API нет.

## Проверка расшифровки на Mac

Из `status` сохраните `last_success.sha256`, `archive_key` и `archive_version`.
Скачайте соответствующую версию `archive.tar.age` через консоль PS Cloud.
Затем локально выполните, подставив путь и SHA-256:

```bash
python3 deployment/backup/verify-cloud-download.py \
  --archive /Users/johnycarlson/Downloads/archive.tar.age \
  --identity /Users/johnycarlson/oxus-backup-keys/production.agekey \
  --destination /Users/johnycarlson/oxus-cloud-restore-check-20261107 \
  --sha256 SHA256_FROM_STATUS
```

Каталог назначения не должен существовать. Проверка сверяет шифротекст,
проверяет аутентификацию `age`, распаковывает только 6 ожидаемых обычных файлов
в приватный каталог и проверяет размер/SHA-256 всех пяти артефактов по манифесту.
Каталог содержит расшифрованные данные и секреты приложения: храните его приватно.

Это не восстановление PostgreSQL/Redis/MinIO в работающие сервисы.
`restore_exercised` остаётся false до отдельной проверки восстановления всего
стека в изоляции. Производственные данные этой командой не перезаписываются.

## Состояние и отключение

```bash
python3 /usr/local/lib/oxus-backup/oxus_cloud_backup.py status
journalctl -u oxus-cloud-backup.service -n 30 --no-pager
systemctl disable --now oxus-cloud-backup.timer
```

Отключение timer сохраняет локальное расписание, облачные архивы и текущую
передачу. Не удаляйте `pending.json`, spool и multipart journal во время
незавершённой передачи. Смена recipient, бакета или credential target требует
отдельного пересмотра; installer существующую отличающуюся конфигурацию не
перезаписывает.

Проверки разработки (S3 полностью подменён, используются синтетические данные):

```bash
python3 -m unittest discover -s deployment/tests -p 'test*backup.py'
bash -n deployment/backup/install-cloud.sh
```

Для всех проверок нужны `age` и `boto3`; без них соответствующие проверки
совместимости/реального шифрования помечаются skipped, а не считаются пройденными.
